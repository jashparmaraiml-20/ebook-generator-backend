Chapter 2: The Foundation — Understanding the Basics
Reframing Intelligence: From Models to Systems

To build effective multi-agent workflows, one must first internalize a critical distinction: an AI model is not an AI system. A model generates outputs; a system produces outcomes. This distinction underpins the entire architecture of agent-based design.

A large language model (LLM) is a probabilistic engine trained to predict tokens. In isolation, it lacks persistence, intention, and structured interaction with the external world. An AI agent, by contrast, is an operational construct that wraps a model with additional capabilities:

Memory

Tool access

Decision-making logic

Execution pathways

When multiple agents are orchestrated together, they form a multi-agent system (MAS)—a coordinated network designed to achieve complex objectives through distributed intelligence.

Callout:
Treat the model as the “cognitive core,” but never confuse it with the full system. The system is what delivers value.

Core Components of an AI Agent

An AI agent can be decomposed into five foundational components. Mastery of these elements is essential for designing robust systems.

1. Perception Layer

This layer ingests inputs from various sources:

User prompts

APIs

Databases

External documents

It transforms raw data into structured context that the model can interpret.

2. Reasoning Engine

The reasoning engine leverages the LLM to:

Interpret instructions

Decompose tasks

Generate intermediate steps

Advanced agents employ techniques such as chain-of-thought reasoning, tree search, or iterative refinement to improve output quality.

3. Memory Systems

Memory enables continuity and learning across interactions. It can be categorized into:

Short-term memory: Context windows, session data

Long-term memory: Vector databases, knowledge graphs

Episodic memory: Logs of past actions and outcomes

Without memory, agents are stateless and incapable of adaptation.

4. Tooling Interface

Agents extend their capabilities through tools:

Web search APIs

Code execution environments

CRM systems

Data pipelines

Tool use transforms agents from passive responders into active operators.

5. Action Layer

This layer executes decisions:

Sending messages

Triggering workflows

Writing to databases

Calling external services

The action layer closes the loop between reasoning and real-world impact.

Taxonomy of Agents

Not all agents are created equal. Understanding different agent types allows for more precise system design.

1. Reactive Agents

Respond directly to inputs

No internal planning

Suitable for simple, stateless tasks

2. Deliberative Agents

Plan before acting

Capable of multi-step reasoning

3. Tool-Using Agents

Invoke external tools dynamically

Extend beyond model limitations

Essential for real-world applications

4. Collaborative Agents

Communicate with other agents

Share context and intermediate results

Enable distributed problem-solving

5. Autonomous Agents

Operate with minimal human oversight

Continuously adapt based on feedback

Often incorporate all previous types

Callout:
The most powerful systems combine multiple agent types, each optimized for a specific role.

Key Terminology and Concepts

The Reality of Failure in Agent Systems

No multi-agent system—regardless of sophistication—operates flawlessly under all conditions. A Systematic Debugging Framework

Before addressing specific issues, it is essential to adopt a consistent debugging methodology.

Step 1: Isolate the Failure Point

Identify which agent or interface is producing incorrect output

Use logs to trace input-output flow across the system

Step 2: Classify the Error

Structural (format mismatch)

Semantic (incorrect reasoning)

Operational (timeouts, API failures)

Step 3: Reproduce the Issue

Use the same input to verify consistency of failure

Determine if the issue is deterministic or probabilistic

Step 4: Apply Targeted Fixes

Adjust prompts, schemas, or routing logic

Avoid broad changes that introduce new variables

Step 5: Validate and Monitor

Retest with multiple inputs

Track whether the issue recurs under different conditions
